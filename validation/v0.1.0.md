- 提供单文件直接激活入口、标准 SKILL 入口、持久状态协议、外部实验指南与回传模板。
- 实现无第三方依赖的 Python 状态工具：init、context、commit、validate、export。

- 16 项 CLI 合约测试已实际通过（3.243 秒），包含独立进程恢复、待验证状态保留、证据/版本不匹配关闭拒绝、重开、版本冲突、幂等、历史保留、锁、符号链接及无覆盖导出。
- Skill Creator 的 quick_validate.py 返回 Skill is valid；它只检查技能格式。


## 独立 Agent 受控演练

以下为作者记录的交付观察，原始演练轨迹未随公开包发布，外部读者尚不能独立复核。使用无任务历史的子 Agent，读取实际单文件入口；提供桌面告警台的虚构需求，逐轮输入。材料始终标为 controlled-fixture。

- F-1：从需求建立确认/交接关注；保留文档与推断边界，没有根据告警数量套用降低密度的改版，也没有修改产品。
- F-2：收到仅修正文档拼写的下一轮输入后，自行选择 after-change / none；保留原关注 ID、原证据版本和未验证状态，没有新建改版任务。
- F-3：收到业务定义、否决新增列表的反馈及无运行证据的实现说明后，保留原问题 ID，记录已否决方案，两个关注均为 awaiting-validation / unverified；没有把实现声明当成通过证据。
- F-4：另一个无任务历史的新 Agent 仅读取协议和 F-3 交接文件，正确恢复“确认等于本人接手，不代表故障解决”、不新增第二列表的决定及两个待验证关注；下一步指向取得运行产物和真实任务观察，未宣称中断期间持续观察。

上述观察支持这些 Agent 在这个受控情境中执行了协议；F-4 只检查读取恢复与判断，没有验证新的持久化提交。它们使用同一宿主，未做普通 Agent 对照，不证明其他宿主的触发可靠性或真实用户效果。演练为检查完整性特意要求输出完整 transcript 状态，产生明显的输出体积成本；这不是日常默认输出，实际外测应分别记录文件模式与聊天接力模式的维护负担。
